## Suggestions re: images (beyond the two-track request)

1. **Build C3 (book workflow map) now, out of band** — it's referenced
   in prose in Chapter 1 §1.6 and will anchor the reader's mental model
   for the entire book; worth prioritizing even outside strict per-tick
   pacing, similar to how front matter was done once outside the
   per-chapter cadence.
2. **Standardize a visual style** for Track 1 diagrams before building
   many of them — one consistent color palette / shape vocabulary
   (e.g. reuse the front-matter callout box colors: blue #2b6cb0 for
   process/flow, orange #c05621 for pitfalls/decision points, green
   #2f855a for agency/compliance nodes) so 30+ chapters' diagrams look
   like one coherent book, not a patchwork of ad hoc styles.
3. **Decide a rendering tool/format now, not per-diagram.** Options:
   - Mermaid syntax → rendered via `npx -y @mermaid-js/mermaid-cli`
     (no global install needed; Node v18+ already on this machine).
     **Render as PNG (`-e png --scale 2`), not SVG.** Mermaid's SVG
     output uses HTML `<foreignObject>` elements for text labels,
     which Typst's SVG importer does not fully support (`typst compile`
     emits an "image contains foreign object" warning and the text can
     render incorrectly/blank in the PDF) — confirmed directly in this
     project. PNG at 2x scale avoids the issue entirely and still looks
     crisp at book-page resolution.
   - **Prefer `flowchart LR` (left-to-right) over `flowchart TD`
     (top-down) for any diagram with more than ~5 nodes.** A top-down
     chart with 8 stacked boxes renders at a tall, narrow aspect ratio
     (confirmed: 8 TD boxes came out ~1200x3400px) that either forces
     a tiny `width:` in Typst (text becomes unreadably small) or spills
     across multiple PDF pages when sized to be readable. The same
     content as `flowchart LR` rendered at a sane 1568x194px landscape
     ratio and fit cleanly on one page at `width: 100%`. Reserve
     top-down orientation for genuinely hierarchical content (org
     charts, decision trees) where top-down is the natural reading
     direction, not for linear sequences/pipelines.
   - Native Typst `#diagram()` / `cetz` package drawings — stays
     entirely inside the Typst toolchain, no external renderer
     dependency, but more verbose to author for complex flowcharts.
     Worth reconsidering if Mermaid's rendering quirks cause more
     trouble later (e.g. very large multi-branch diagrams).
   - Keep the `.mmd` source files alongside the rendered `.png` output
     in `images/conceptual/` (e.g. `ch01_book_workflow_map.mmd` +
     `.png`) so diagrams are editable later, not just static images.
4. **Figure captions and cross-references.** Every inserted image in
   Typst should use `#figure(image("..."), caption: [...])` with a
   label (`<fig-ch01-workflow>`) so later chapters can cross-reference
   "see Figure 1.1" rather than re-describing the same structure in
   prose — Typst's `#figure` auto-numbering makes this nearly free.
5. **Placeholder discipline for R-generated images.** Since Dr Aswath
   supplies these after the fact, each chapter's `.typ` file should
   include a clearly marked `// TODO-IMAGE: <description>` comment (not
   a broken `#image()` call that would break compilation) at the exact
   point an R-generated chart belongs, so dropping in the real file
   later is a one-line change, and the book still compiles cleanly in
   the meantime.
6. **Don't let Track 1 diagram-count balloon late in the book.** Parts
   IV-V (decision modelling, uncertainty/VOI) are exactly where
   structural diagrams (Markov state diagrams, decision tree
   structures, DAGs for causal inference in Ch.15) are most valuable
   AND most numerous — worth flagging now that those chapters may need
   2-3 diagrams each rather than the 1 per chapter seen so far, so the
   per-tick pacing assumption may need revisiting once the pipeline
   reaches Part III-IV.
