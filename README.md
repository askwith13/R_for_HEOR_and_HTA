# R for HEOR and HTA — Book Project

Progressive, chapter-by-chapter book draft, written in Typst, with
Markdown context summaries maintained alongside for continuity across
writing sessions and cron ticks, plus a companion code repository
auto-extracted from the book's own typeset code blocks.

## Compiling the book

```
cd typst_project
typst compile book.typ book.pdf
```

Typst binary installed at `~/.local/bin/typst` (v0.15.1, musl static
build from github.com/typst/typst releases — not available via apt).

## The companion code repository (`code/`)

Every R (and occasional bash/Dockerfile) code block in the typeset
chapters is extracted into its own standalone, numbered file under
`code/chNN_slug/`, regenerated by:

```
python3 ~/.hermes/scripts/extract_chapter_code.py          # all chapters
python3 ~/.hermes/scripts/extract_chapter_code.py --chapter 10   # one chapter
```

**Never hand-edit files inside `code/chNN_slug/` directly** — edit the
chapter's `.typ` source and re-run the extractor; it deletes and
rewrites each chapter's folder fully from current source every time,
so a direct edit there will be silently overwritten on the next run.

Each chapter folder also gets an honest package manifest,
`renv.lock`, via:

```
python3 ~/.hermes/scripts/generate_chapter_renvlock.py
```

This is NOT a true `renv::snapshot()` lockfile — it lists every
package the chapter's code references, with a REAL version number
where that package is actually installed on the machine that drafted
the book, and an explicit `NOT_VERIFIED_IN_THIS_ENVIRONMENT` marker
for packages referenced but not (yet) installed here. See the
`_comment` field inside any chapter's `renv.lock` for the full policy.
A true frozen lockfile requires installing every package and running
a real `renv::snapshot()` inside that chapter's own project directory
before public release.

  `companion_website.typ`'s stated structure but has nothing to hold
  yet. See `solutions/README.md`.

## Pace

One chapter every cron tick (5-hour interval), via the
`heor-hta-book-writer` cron job. Front matter was written first,
outside the cron pace, to establish the Typst infrastructure
(callout box functions, page styling) that every chapter reuses.

## Quality gate

Every chapter is self-critiqued by Claude, then scored by Jev
(TypeSafe AI) across 6 dimensions (see `progress/chapter_quality_rubric.md`).
5 dimensions (coverage, technical_correctness, code_validity,
agency_grounding, internal_consistency) are scored against a compact
structured summary of the chapter; the 6th (readability) is scored
separately against the chapter's actual prose text (see
`jev_score_readability_prose.py` and the rubric doc for why this
split exists). Any dimension below 6/10 triggers one revision pass
before the chapter is marked complete in `book_progress.json`; two
consecutive low scores on the same dimension stops the loop and flags
the issue for the author rather than revising indefinitely.
